# Combined Education review and recovery

On 6 October 2026, two deployed combined Goal/Budget/Education requests were withheld for factual qualification with `repairable=false`. Both had estimated correction headroom below the 50,000-token ceiling. The separate Goal-context Education follow-up passed. Production intentionally retains fixed diagnostic categories and counts, not the rejected prose or private reviewer notes, so the exact original sentences remain unverified.

A backend-shaped synthetic replay reproduced a provenance failure: the reviewer treated the second model-knowledge topic as outside a single shared label. Repeating the visible label immediately before that topic made the same draft pass. Another replay showed a contract retry changing repairability while still describing an Education-only qualification defect. AWS task revision 50 omitted role overrides; CloudWatch confirmed every call used low reasoning with a 1,600-token limit, differing from the local/template policies.

The active source application accepts only v9 and rejects legacy prompt versions at startup. v9 retains the v8 Education contracts and adds [conditional financial dependencies](conditional-financial-dependencies.md); deployment and live v9 acceptance remain pending. Archived prompt files remain available for explicitly pinned offline evaluations. Prompt set v8 keeps the v6 routing/retrieval semantics and introduces section-specific independent review. The formatter labels each model-knowledge topic and records character ranges, provenance and topic without duplicating explanation text. Compliance receives those ranges in `review_sections`, along with specialist ownership, the draft and the existing approved evidence. A label identifies provenance, not factual safety; source claims still require supporting passages.

The reviewer returns `blocking_issues` with a supplied `section_id` and a brief correction requirement. `missing_points` covers unanswered requirements only; `complete=true` requires an empty completeness list, while safety defects remain explicit. Safe but incomplete answers also require section-specific correction requirements matching every missing point. The v8 orchestrator requires server-derived repair eligibility for these answers as well as blocked drafts. Financial or unowned completeness gaps cannot enter Education correction. The model does not choose `repairable`. The server admits correction only when every blocking issue belongs to Education, the request is allowed, financial language is safe and categories are limited to citation attribution or factual qualification. Budget/Goal, prohibited, unsafe and unowned synthesized defects remain withheld. Unknown section references receive one bounded contract correction; a repeated invalid verdict fails closed as `review_contract_unverified`.

Recovery still reuses sealed Education grounding, permits only one correction, preserves completed financial inputs, calculations and text, and runs another independent review of the full combined answer. Failed or unavailable corrections retain the original review and privacy-safe diagnostics. Requirements, section text and rejected prose stay out of logs and persisted decision traces. Capability permissions and the separate Education/Policy retrievers remain intact.

The total request ceiling is 80,000 input/output tokens. Global defaults are `MODEL_REASONING_EFFORT=medium` and `MODEL_MAX_TOKENS=3200`; smaller routing/planning policies explicitly override those defaults. Budget, Goal and Spending use medium reasoning with 3,200 output tokens each; Education uses medium/4,000 and Compliance medium/3,000. Routing and planning retain smaller role limits. Application defaults load the same packaged policy even when role overrides are absent. The canonical policy lives in `apps/ai-service/app/core/model-role-policy.json`; release loads, applies and verifies it instead of inheriting absent/stale ECS role configuration. Tests check agreement with `.env.example` and the bootstrap template. Deployment smoke verifies v9 and the reasoning/output limits observed in Budget model-call telemetry, including Compliance calls when present. Explicit lower ceilings, call limits and deadlines remain enforced.

Typed schemas constrain shape; application validation still checks section references, correction ownership and safety. See the [official OpenAI Structured Outputs documentation](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses). No model or API migration is part of this change.

Regression coverage exercises per-topic labels in both locales and lead orders, exact draft ranges, complete-but-correctable answers, invalid references, financial/prohibited/unsafe ineligibility, preserved combined calculations, one independent rereview, lower explicit budgets, and missing/stale release overrides. A deployed Edge retest is required after this version is released; local regression checks do not establish deployed acceptance.

A bounded local GPT-6 Luna replay of the backend-shaped combined December request passed v8 independent review in seven calls using 34,557 tokens. Telemetry confirmed medium/3,200 for Budget and Goal, medium/4,000 for Education, and medium/3,000 for Compliance. A preceding replay was withheld after Compliance misread Budget deferring feasibility to Goal as a contradictory financial conclusion; v8 now distinguishes that scope statement from an actual contradictory financial conclusion. These synthetic replays are integration evidence, not repeated or deployed acceptance.

Final local verification: 1,773 AI regressions passed (one skipped), 272 infrastructure regressions passed (five skipped; four subtests passed), and 56 focused release/policy/smoke checks passed after adding stale global-setting checks. Ruff, whitespace validation and the Chinese source-code scan passed. Wheel packaging of the canonical policy and updated defaults was verified. The deployed app still needs release and Edge acceptance testing.
