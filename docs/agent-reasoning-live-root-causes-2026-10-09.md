# Root causes of the 9 October live reasoning failures

This records the deployed source before the fixes. The subsequent
[local claim recovery](orchestration-local-claim-recovery-2026-10-09.md) addresses
the confirmed defects without changing these historical observations.

This diagnosis uses the [42-turn live report](agent-reasoning-live-test-results-2026-10-09.md), its [selected trace evidence](evaluation-evidence/agent-reasoning-live-v10-2026-10-09.json), and the source deployed as `dc01ebd5403c8a447be66dd1ebbfc21da039a393` with prompt set v10. The checkout used for source inspection was `e9efb7d`, whose subsequent commit recorded deployment documentation. No application fixes or further live prompts were executed during diagnosis.

Financial specialist selection, required dependency edges and required parallel execution matched the acceptance catalog. The failures occur in narrative grounding, review and correction. All eight withheld turns initially recorded `request_allowed=true`, `answer_complete=true`, `repairable=true` and `factual_qualification`. Policy evidence was retrieved; these runs did not report `policy_evidence_missing`.

## Implementation mechanisms

### Trend magnitude and arithmetic direction are conflated

`compute_category_trends` labels changes between −5% and +5% as `stable`. Food's exact decrease is present alongside that label. The label is useful as a significance summary but does not mean an unchanged amount. The writer and reviewer lack an enforced distinction between arithmetic equality and approximate stability.

Source: [spending_analysis.py](../apps/shared/coach_math/spending_analysis.py).

### Review ownership includes application-generated presentation

`InvestmentEducationAgent._format_summary` generates numbered labels. `draft_review_sections` exposes those `topic_label` sections with Investment Education ownership. The same repair path used for model-authored prose then attempts to alter a label that is not editable through the writer's permitted fields.

Sources: [investment_education.py](../apps/ai-service/app/agents/investment_education.py), [review_sections.py](../apps/ai-service/app/core/review_sections.py).

### Corrections regenerate structured answers under character-level constraints

The Education correction reruns its structured writer using the sealed original grounding. After rendering, `validate_text_corrections` rejects any character change outside the independently identified ranges. This checks preservation rather than JSON validity. Therefore the generic `INVALID_STRUCTURED_RESPONSE` in cases 26a and 13R should not be described as malformed JSON: the traces show successful schema parsing before rejection. The source maps this error to the protected-text validator, but it does not record a specific fixed predicate code for that failure.

Sources: [base.py](../apps/ai-service/app/agents/base.py), [narrative_corrections.py](../apps/ai-service/app/core/narrative_corrections.py), [structured.py](../apps/ai-service/app/models/structured.py).

### Postprocessing can restore a claim that repair removed

After validating a synthesized answer, `_synthesize` appends specialist uncertainties and `education_gap_message` when applicable. Draft-only repairs preserve specialist results. As a result, an unwanted gap statement can be removed by the repair writer and then restored from those original results. An offline diagnostic reproduced this without network calls or financial writes.

The default sentence is: “The approved knowledge base does not contain enough information to answer this question.” It is 88 characters. For a partially answerable question this blanket statement is broader than identifying the unsupported part, and limited retrieval alone does not establish what the entire corpus contains. The approved EV-06 policy already requires support and completeness to be assessed per requested part.

Sources: [orchestrator.py](../apps/ai-service/app/orchestrator.py), [education_access.py](../apps/ai-service/app/agents/education_access.py), [evidence_and_citation.md](../knowledge/policy_controls/documents/evidence_and_citation.md).

### Conservative repair forecasting denies corrections before timeout

`repair_time_estimate` reserves twice the sum of the slowest observed duration for each required role, accounting for a writer/reviewer pass and their possible contract corrections. An unseen synthesizer uses the slowest observed call in the workflow. The orchestrator requires this estimate to fit inside the remaining deadline. This explains the confirmed admissions rejected in 4, 25R, 29 and 35. It is a forecast, not an observed timeout; a declined repair may or may not actually have fit.

Sources: [repair_budget.py](../apps/ai-service/app/core/repair_budget.py), [orchestrator.py](../apps/ai-service/app/orchestrator.py).

### A response-level veto withholds every section

`_finalize` replaces the entire combined answer and withholds every specialist result when the final compliance result is blocked. There is no separately reviewed partial-release path at this stage. Thus an Education defect in 13R also withholds the Spending answer, and a local defect in 29 removes useful supported education. This is the failure's amplification mechanism, not a recommendation to publish unreviewed sections.

Source: [orchestrator.py](../apps/ai-service/app/orchestrator.py).

## Why outcomes vary

Same build, prompt hash and financial records do not fix generated text, semantic review verdicts, contract-correction count or provider latency. Case 13's first review approved its answer; its repeat required a qualification and entered a recovery path that failed. Cases 25 and 29 both failed twice, but one attempt admitted repair while the other declined it on the time forecast.

The saved model calls report `temperature_supported=false`, consistent with the OpenAI reasoning gateway omitting the configured temperature. Attributing this inconsistency specifically to the configured `agent_temperature=0.35`, or promising that lowering it would resolve the problem, would be unsupported.

## Diagnostic limits

Risk & Compliance is the reviewer that produces the blocking verdict; the orchestrator enforces release and decides whether correction can run. Retrieval of Policy evidence succeeded in these runs. The evidence does not establish that Policy documents prohibited these requests, nor that every factual-qualification verdict was accurate.

The AI service preserves safe review metadata in withheld results, but the backend's `sanitize_blocked_agent_results` rebuilds every result with `data={}`. This is a confirmed diagnostic gap: final agent metadata disappears from saved/exported blocked results, although safe audit events retain the initial review and correction decisions. Rejected draft text is intentionally absent, limiting validation of the model's substantive judgment.

Source: [backend schemas.py](../apps/backend/app/domain/schemas.py).
