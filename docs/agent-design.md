# Agent Design

## Current Execution Mode

The primary runtime is a model-driven multi-agent workflow. LangGraph executes boundary inspection, bounded read-only follow-up resolution, model routing, one or more specialist agents, model synthesis, and an independent Risk and Compliance review. The deployed model gateway uses the OpenAI Python SDK and Responses API with GPT-6 Luna with low default reasoning and medium specialist/reviewer role policies. The gateway omits temperature because this model does not accept that setting with reasoning enabled.

The architecture is hybrid rather than unconstrained. Deterministic calculators, retrieval ranking, PII redaction, prompt-injection checks, and tool allowlists produce trusted grounding and hard policy decisions. Models choose agents and interpret that grounding, but cannot name or invoke arbitrary tools. Pydantic validates every model response before the graph advances; invalid output fails closed as a sanitized `503` response.

`MODEL_PROVIDER=local_fixture` is an explicit offline adapter for unit tests, fixed CI regression datasets, and local Compose. It is deterministic by design and configuration validation rejects it outside `local` and `test` environments. It is not the deployed agent behavior.

## Roles, Memory, And Tools

| Agent | Model-driven responsibility | Current memory | Approved tools and capabilities | Explainability and safety |
|---|---|---|---|---|
| Spending | Aggregate recent transactions and publish `transaction_category_totals` | Request-scoped financial snapshot | `transaction_summarizer` | Uses only supplied transactions; reports arithmetic and avoids lifestyle inference |
| Budget | Collect planning inputs, propose category limits, check affordability, capture confirmed budgets; retain legacy baseline and `monthly_savings_capacity` support | Owned conversation draft; role-scoped income, recurring expenses and aggregate planning context | Direct tools: `budget_planner`, `budget_calculator`; conditional capabilities: Spending `transaction_category_totals` for Budget's own work and `education_context` through the orchestrator | No inferred take-home basis or savings target; labeled spending suggestions; backend funding checks and confirmation before saving |
| Goal Strategy | Project user-defined savings goals, request savings capacity for feasibility, and conditionally explain investment concepts | Request-scoped goals plus orchestrator-resolved capabilities | Direct tool: `goal_projection`; conditional capabilities: Budget `monthly_savings_capacity` for feasibility and `education_context` through the orchestrator | Saved arithmetic needs no Budget or income; preserves deterministic projections; requests evidence only for allowlisted investment topics; cites approved evidence or reports an evidence gap |
| Investment Education | Explain general investment concepts | Sanitized request, bounded owned conversation context and approved education context | `education_retriever` | Retrieves first; distinguishes cited evidence from labeled model background; reports gaps and avoids product instructions |
| Risk and Compliance | Validate requests and specialist outputs against governed policy evidence | Sanitized request, specialist evidence, and approved policy context | `policy_retriever` | Uses only the separate Policy collection, sanitizes retrieved text, records policy provenance, and fails closed when current policy evidence is unavailable |

No specialist has private or self-managed durable memory. The backend persists synthetic profiles, transactions, monthly budgets, goals, chat history, and privacy-safe orchestration traces, then assembles a minimized request-scoped snapshot. Capability results live only for the current orchestration run. Policy `data-lifecycle-v1` now provides owner export/deletion, versioned future-memory consent, automatic chat/trace retention, synthetic-user expiry, and isolation tests; durable memory remains disabled until purpose-limited storage, correction, encryption review, and an explicit activation decision are implemented.

For follow-up questions, the backend supplies at most eight messages from the owned conversation, each bounded to 1,500 characters. Blocked assistant content is omitted and the AI sanitizes this dialogue again. The router, regular Spending/Budget/Goal Strategy reply writers, Investment Education and budget/goal draft extraction receive this context. Financial reply writers use a separate `conversation_context` prompt field so dialogue never becomes tool grounding or capability evidence. Saved records and deterministic grounding remain authoritative for calculations. Conversation ownership and revision are rechecked before saving the reply.

Migration `20261002_0014` adds backend-owned structured facts and clarification state to the same retained chat. Explicit supported statements, unambiguous answers and corrections retain their source positions and `user_reported` status beyond the eight-message window. The router, role-minimized writer/draft prompts and Goal Strategy preflight receive `session_context`; uncertainty never supplies a calculation input. Local recall and spending/budget follow-ups use the same session boundary, and recognized fact corrections bypass expense capture. Transaction clarification queues are now keyed by user and chat, but remain process-local with their existing ten-minute TTL. A rolling extractive summary retains up to six older approved exchanges (2,400 excerpt characters), prioritizing preferences/objectives and retaining source positions. It is sanitized, minimized by specialist topic and kept outside grounding and draft extraction; it never establishes consent or pending actions. Session state follows chat export, deletion and retention; cross-chat durable agent memory remains disabled. See [Session context](session-context.md) for supported inputs, limits and rollout.

Investment Education retrieves approved passages for the requested concepts first. Stable concepts missing from those passages may be explained in a separately labeled model-knowledge section; current prices, eligibility rules and excluded topics do not receive this fallback. The combined answer receives independent safety and completeness review. One bounded repair may fill missing details, followed by a fresh review; failed repairs retain only the original reviewed answer. Citations use validated source IDs and server-rendered document-title links. The chat and reopened history show the cited title, organization, captured date and URL; unused retrieved sources are not presented as support for model-only answers. A source date is not a live verification of its contents.

A resolved conversational subject does not replace the current task. For example, “For that savings goal, explain diversification and investment time horizon” retains Education routing and current concepts even when “that goal” resolves to a persisted Goal Strategy referent. A plain “explain that more simply” still follows the referenced specialist. Neither reference authorizes draft capture or supplies financial evidence. The router's `budget_capacity_query` identifies calculations and goal affordability assessments using saved savings capacity; these bypass budget extraction while explicit budget planning and saved-record commands retain their normal paths.

When Investment Education is selected alongside Budget/Goal, it owns the investment explanation. Its validated public concept plan scopes the writer's question to education. Financial specialists retain their deterministic calculation dependencies and answer the financial part without requesting duplicate education context. Budget capacity providers defer goal feasibility to Goal Strategy. Missing inputs or sources in one role's deliberately minimized grounding must not become claims that the complete answer lacks them. Genuine missing inputs and source qualifications remain visible in the responsible role's answer. Goal emergency-fund assessments keep their required evidence dependency. Under v6/v7/v8/v9, combined read-only Budget/Goal/Education answers preserve specialist paragraphs and source qualifications without a second model rewrite, then receive the full independent review. Drafts, blocked results, missing inputs and other specialist combinations retain the existing synthesis behavior.

One education correction is also available within these combined read-only answers. It reuses the sealed, server-created Education grounding and keeps completed financial tasks, calculations and text unchanged. Query planning, evidence assessment and financial writers are not repeated. Correction feedback concerns only the Education answer; financial defects cannot be repaired by changing Education text. A fresh review examines the complete combined response. Admission checks known usage, the latest Education writer/reviewer forecast, source authority, the call reserve and deadline against the 80,000-token default. An unavailable or rejected correction never releases an unreviewed draft.

## Communication

The backend calls one private AI service API. Inside that service, LangGraph passes typed state between nodes and Pydantic models validate all model decisions. The orchestrator creates a role-scoped `AgentTask`, so Spending receives only recent transactions, Budget income and recurring expenses plus backend-owned aggregate planning context for planning tasks, Goal Strategy only goals, and Investment Education only its sanitized question and risk constraint. Investment Education can call `education_retriever` directly, but its retriever receives only canonical topic labels—not the raw question, identifiers, or personal values. Budget and Goal Strategy can request the typed `education_context` capability only for allowlisted investment topics and use the same topic-only query boundary. The orchestrator invokes the retriever, caches the result within the run, quarantines unsafe chunks, and returns approved evidence. Compliance does not query the Education knowledge base, and Spending remains retrieval-free. Retrieved evidence is carried into synthesis and independent Compliance review. A2A is deferred because agents share one owner and runtime; MCP is deferred because the small tool set is governed by a local typed allowlist.

Specialists do not invoke one another. With prompt sets v3 through v9, an eligible specialist first returns a schema-validated dependency-planning decision: `ready`, `needs_dependency`, or `needs_input`. A dependency request names an allowlisted capability, never another agent. The orchestrator authorizes it through the deterministic registry, fingerprints the required input, reuses or schedules an agent provider, invokes an approved tool provider, records the dependency edge, rejects cycles, and resumes the requester with the minimal `CapabilityResult`. Capability requester authorization is separate from direct tool execution permission: Budget and Goal Strategy can request `education_context`, while only Investment Education can execute `education_retriever`. The orchestrator uses Investment Education's grounding logic for this tool dependency without scheduling its full narrative task. A user-input request returns typed questions without calling more specialists.

The scheduler runs independent ready tasks concurrently, while preserving dependency order. A request can therefore start Budget and another independent specialist together, or discover the multi-hop chain Goal Strategy -> Budget -> Spending when the model determines transaction totals are needed. Required dependency failures and cycles fail closed. Optional dependency failures become explicit warnings, and bounded retries, per-agent timeouts, dependency rounds, provider calls, model calls, and model tokens prevent runaway execution.

## Model Strategy

The deployment calls GPT-6 Luna through the OpenAI Responses API and retrieves Education and Policy evidence from separate checksum-verified corpora packaged with the AI service. Each collection is independently pinned by corpus version at runtime; stale, malformed, unapproved, or wrong-version sources are rejected. Prompt set v9 is the current source target; it retains v8's section-specific Education review and adds conditional financial dependencies. See [combined Education recovery](combined-education-recovery.md) and [conditional financial dependencies](conditional-financial-dependencies.md). Deployment and a fresh repeated live evaluation are required before treating v9 routing as accepted. The selection rationale and prior model evidence are in [model selection](model-selection.md).

The selection harness compares at least one lower-cost model against the baseline on:

- Routing and tool-selection accuracy.
- Unsafe-advice refusal and prompt-injection robustness.
- Explanation quality and consistency across writing styles.
- Grounded source use and hallucination rate.
- P50/P95 latency, token usage, and estimated cost.
- Provider availability and the documented data-processing geography for the selected data class.

The direct OpenAI API's Singapore residency option covers regional storage, not regional processing. The demo therefore remains synthetic-data only pending a new privacy and location review for personal financial information.

The live evaluator estimates GPT-6 Luna usage at USD 0.10 per million input tokens and USD 0.50 per million output tokens. These are configurable rate assumptions, not billed-cost telemetry. Recheck the [OpenAI model card](https://developers.openai.com/api/docs/models/gpt-6-luna) before a formal evaluation and record the rates with token totals.

## Prompt And Model Change Control

Prompt, model, retrieval, tool, capability, or policy changes are validated with regenerated evaluation evidence. A change that alters instruction meaning increments the prompt-set version. Prompt set v9 adds conditional Goal capacity and role-scoped Budget Spending selection while retaining v8 scoped Education review. Prompt set v3 introduced typed, model-generated dependency planning; prompt set v4 added grounded Budget and Goal Strategy Education instructions while keeping capability authorization deterministic; prompt set v5 added a machine-enforced Investment Education citation and uncertainty contract; v6 preserves fine-grained topic/intent and evidence gaps, restricts model citations to server-rendered approved markers, and withholds every generated explanation when Compliance blocks. Current audit metadata includes model provider, model ID, prompt version, route rationale, trace ID, safety findings, task lifecycle, dependency edges, retrieval consumers, model-call duration, token usage, and separate Education/Policy source provenance without recording raw prompts. The backend persists this privacy-safe trace for profile-authorized retrieval. Live evaluation estimates cost from audited tokens and recorded price assumptions; add billed-cost reconciliation before production approval.

Durable runs now exist before AI execution and retain incrementally committed decision metadata on failures. See [Durable decision traces](durable-decision-traces.md) for run states, cross-service identifiers, privacy boundaries, retention, and rollout.

## Category budget planning

The first-stage planner is described in [Budget planning](budget-planning.md). The separately versioned `budget-planning-v3` extraction contract captures explicit constraints; an allowlisted deterministic planner produces category proposals and arithmetic. The backend independently checks the merged plan, asks about missing commitments, and persists the confirmed savings allocation separately from expense limits. Planning drafts are backend-managed conversation state, not autonomous specialist memory. Stage two adds explicit method selection and read-only scenario comparisons. The backend computes guidance, stores comparison candidates, and handles explicit scenario adoption before the normal confirmation flow. Stage three routes explicit review requests to owned backend aggregates, derives bounded pace illustrations and adjustment scenarios, and preserves review evidence through adoption and confirmation. Scheduled reviews, general forecasting and rollover remain deferred.
