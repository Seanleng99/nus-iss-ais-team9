# Coach response remediation

Implementation started 3 October 2026; verification continued 4–5 October 2026 (Singapore time).

This change addresses the findings in [the original audit](coach-response-rigidity-audit-2026-10-03.md). The audit remains a record of the original behavior. Deterministic financial calculations, source validation, ownership checks and explicit confirmation of saved changes remain necessary controls. The changes let the model interpret intent and compose an answer inside those controls.

## Completion status

Code changes now address all 28 findings, including the previously outstanding implementation work in A04, A06, A07, A13, A15, A22, A23, A24 and A28. The updated API key worked in a complete OpenAI run: 21/21 synthetic scenarios passed automatic checks across 28 conversation turns, and separate assistant review found the final answers met their specific qualitative rubrics. This is implementation closure and bounded local verification; human acceptance, general response quality and rollout checks remain separate.

## Model and retrieval design

`MODEL_ROLE_OVERRIDES` is a bounded JSON map of prompt roles to optional `model_id`, `reasoning_effort`, and `max_tokens`. The example environment and AWS task template use `gpt-6-luna` across roles, give specialist writers and final Risk and Compliance review medium reasoning, and use low reasoning for routing, dependency/query planning, synthesis, answerability and action composition/grounding. Writers also receive more output space than routing. These are configured defaults, not live comparison or tuning results. OpenAI reasoning requests omit temperature; changing an inert temperature no longer appears to tune model output. Usage traces retain reasoning tokens separately from total output usage.

The total workflow budget now defaults to 80,000 input and output tokens, increased from 50,000 on 6 October for conversation and specialist headroom, so sourced answers can finish planning, coverage assessment, writing and independent policy review. Per-role output limits and explicit smaller total limits remain enforced. Review context removes exact duplicates while preserving every distinct carried passage, qualification and policy context. Action composition has its own bounded calls and deadlines; failures retain the canonical backend result.

The specialist deadline defaults to 45 seconds, the backend AI deadline to 90 seconds, and the configurable frontend Coach wait to 120 seconds. Normal provider reads allow 30 seconds; OpenAI now honors the configured connect timeout separately. Composition has one 25-second monotonic deadline: writing and grounding reads allow at most six seconds each, while final Risk review uses the remaining window. Explicit shorter limits remain supported. A failed real-provider call with unknown usage prevents additional SDK spending in that workflow. Admission of one factual or citation correction uses the configured specialist window, remaining call budget and estimated token budget. Unsafe requests cannot use this correction path, and the original draft stays withheld until the corrected answer passes fresh independent Risk review. Failed composition transport preserves the backend action and marks unreported usage incomplete.

That correction reuses a private snapshot of the original validated Education grounding, avoiding a second query-planning and answerability cycle for the same request. The snapshot binds the task, sanitized question, prompt/corpus version, source identities, exact quotations, scope and coverage decisions. It is never accepted from user/model JSON, and the correction receives a deep copy; changed authority or request context is rejected. Writing, citation validation and independent policy review still run again. Regressions verify one planner/coverage call, two writer/review calls, rejection of altered source authority, and retention of the original blocked response when correction fails.

Correction admission counts every prior call as consumed tokens, then estimates the next writer/review pair from their latest completed calls with output headroom. Earlier schema-invalid writer attempts are not budgeted again as future work. Real-provider usage must be complete and the private grounding snapshot available; otherwise another correction is refused. Explicit 20,000-token limits, call reserves and the actual per-call hard budget still apply. The recorded six-call 25,883-token case and a 25,983-token variant permit one reviewed correction under an explicit 40,000-token limit; a simulated actual overrun retains the original withheld answer.

Closed typed response schemas use native strict structured output on the initial request. Contracts containing open operation maps retain their schema in non-strict mode and remain subject to local Pydantic validation plus one bounded repair. Schema conversion follows the required-field and closed-object constraints in [OpenAI’s Structured Outputs documentation](https://developers.openai.com/api/docs/guides/structured-outputs).

Education retrieval uses approved, versioned public documents. The semantic query planner decomposes the sanitized request into bounded public subquestions and preserves the resolved mechanism. Convexity has a distinct canonical topic; its governed `bond price` retrieval alias does not replace that subject or expand the fallback scope. Internal subquestions use natural public phrasing and are not sent to retrieval; retrieval terms must belong to public vocabulary or exact governed aliases. Personal fields and instructions remain rejected. Separate semantic assessment cites exact carried quotes; invented quotes and source IDs are rejected. The writer receives those coverage limits. If bounded contract repair fails, the application reports an unverified coverage gap. The writer must leave `uncertainties=[]` and omit verification/retry status from all narrative fields in that case, while retaining conceptual assumptions. Storage ranking remains lexical; corpus checksums, freshness, citations and independent review remain active.

Conversation memory remains bounded: the latest eight messages stay verbatim, with up to six extractive notes for older preferences, objectives and discussion. Semantic observations and referents retain exact source excerpts, positions and attribution; reported values retain correction provenance. Quoted and hypothetical clauses cannot supply personal facts, while unrelated quotations or hypotheticals do not erase a separately attributable statement. A presented subject is referenceable only when it survives reviewed-answer provenance checks; a successful presentation rewrite clears vanished ordered options before merging newly reviewed references. Retrieved context covers up to twelve topics within a 1,200-word budget and reports missing coverage explicitly. Transaction-query totals use the complete owned SQL result; displayed details and coaching snapshots remain bounded and disclose truncation.

The owned snapshot partitions the selected calendar month from the preceding six months of history. Spending analyzes both sets together for trends while preserving separate selected-month totals and date-coverage summaries. Counts, truncation flags, earliest/latest recorded dates and weekday/weekend recorded totals describe the supplied evidence, not proof of a recurring habit or a complete ledger. Dates after the selected month and unsupported currencies are excluded rather than silently mixed into the result.

The backend remains authoritative for reads, saves, cancellation and previews. Post-action composition receives these outcomes alongside reviewed specialist evidence and bounded preferences. It cannot change owned identity or sources. Grounding, citation and policy failures retain the backend response; policy-retrieval failures also retain available consumed-call accounting. Composition uses bounded model calls and timeouts, and action writes stay in the transaction until the exchange is persisted.

Compose loads the private `.env` as an optional file after the example and permits explicit provider selection. Updating `OPENAI_API_KEY` alone does not switch its default fixture provider: use `MODEL_PROVIDER=openai` for live output. The verification helper explicitly selected OpenAI; no running user deployment was switched and the private `.env` was not edited by this work. The optional-file syntax requires Compose 2.24 or later, as documented by [Docker](https://docs.docker.com/compose/how-tos/environment-variables/set-environment-variables/).
